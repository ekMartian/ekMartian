# Analytics and publication

## Public calendar

[Activity JSON](data/activity.json) is the versioned public contract. The schema contains a fixed coverage label, six consecutive completed UTC months, one integer count per month, and the bounded total. The SVG is a deterministic rendering of those fields. A future site can consume the JSON independently of GitHub Markdown. Treat `schema_version` as a compatibility boundary. Future contest integrations should use separate, versioned datasets, independently verified handles, and platform-specific coverage. Competitive programming metrics are currently unconfigured.

The daily GitHub Actions run starts at 03:23 UTC, or 08:53 IST. For a manual refresh, use **Actions → Refresh contribution activity → Run workflow** on the default branch. The collector reads the anonymous GitHub profile calendar and can fall back to a GraphQL query using a read-only workflow token. It requires every day in the reporting window, reconciles overlapping months with the previous release, and stops on unavailable data or a substantial unexplained decrease. The publishing job has write access only to this profile repository and can stage only the JSON and SVG. Failed runs preserve the last published pair. Identical data produces identical files and no commit. A successful run may leave the same date range in place until a month closes. GitHub can delay scheduled jobs and pause them for inactive public repositories.

The calendar follows [GitHub’s contribution rules](https://docs.github.com/en/account-and-profile/reference/profile-contributions-reference). It includes anonymized private contributions shared by the account and reports eligible GitHub contributions across the stated window. A missing or inaccessible calendar, a change in visibility, a repository transfer, rewritten history, branch eligibility, or different author email linkage can change coverage. The continuity check detects large drops and needs human review if a visibility change is intentional. The profile never publishes daily or restricted-only values.

## Private repository collector

Run `python3 scripts/repository_inventory.py` in a private environment with `PROFILE_READ_TOKEN` loaded from a credential store. GitHub CLI and Python 3.11+ are required. The script discovers newly visible public and private repositories through the paginated authenticated inventory. Use a fine-grained token restricted to selected repositories with Metadata and Contents read. Each additional resource owner requires appropriate authorization. The optional `PROFILE_METADATA_TOKEN` may have broader **Metadata read** coverage without source access. It compares repository IDs in memory and returns a count of private repositories the content credential cannot see. A null gap count means the collector lacks an independent baseline. Any additional scope the baseline cannot see remains unknown.

Run this collector daily on an authorized private scheduler or on demand. Keep its credentials and outputs outside the public repository and its workflows. The private collector returns aggregate coverage and source counts for internal review. No private repository or language metrics are wired to public publication. To add these later, agree on the eligible project set and approved categories, define a separate strict release schema, and give the publisher access only to the sanitized output. Do not pass through the collector’s output as-is.

The measurement counts known source extensions at the default-branch tip. It excludes forks, GitHub templates, archived and disabled repositories, the profile repository, empty trees, exact duplicate tree hashes, symlinks, dependency directories, conventional build and generated paths, and common generated and minified filename patterns. These are conservative path-based rules. Custom generators, nonstandard vendor locations, imported history, near-duplicate projects, or coursework in ordinary repositories need a reviewed classification policy before release. Skipped and inaccessible trees are counted separately. Bytes measure source composition and the 90-day activity number uses last push dates. They do not measure coding time, expertise, authorship, or distinct products. Historical views need snapshots collected over time.

## Maintenance

Edit the README directly to add a public project, link, or verified achievement. Review project names, images, metadata, and URLs against the disclosure policy before committing. Workflow output contains only the allowlisted calendar snapshot. The release schema accepts no repository strings, URLs, filenames, credentials, or free text from upstream data.

Run `python3 -m unittest discover -s tests` and `python3 scripts/activity.py check` to validate the generator and public snapshot.
